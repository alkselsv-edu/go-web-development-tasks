# Роутинг в Fiber веб-приложении

Представим, что вы разрабатываете веб-приложение для управления лайками постов в социальной сети. Вам необходимо реализовать обработчики двух HTTP-запросов:
* `GET /likes/{post_id}` возвращает количество лайков поста с идентификатором *post_id*.
* `POST /likes/{post_id}` увеличивает количество лайков поста с идентификатором *post_id* на 1.

Лайки хранятся в глобальной переменной *"postLikes"* в виде `map[string]int64`, где ключом является идентификатор поста (например *12345*), а значением — количество лайков этого поста.

Если при HTTP-запросе `GET /likes/{post_id}` пост с идентификатором *post_id* не найден, то возвращается код ответа *404 Not Found*.

Если при HTTP-запросе `POST /likes/{post_id}` пост с идентификатором *post_id* не найден, то он создается и возвращается код ответа *201 Created* и количество лайков.

Если пост с идентификатором *post_id* уже существует, то возвращается код ответа *200 OK* и количество лайков.

Пример HTTP-запроса с лайком поста:

```bash
curl -X POST http://localhost:8080/likes/12345
```

Пример ответа:

```bash
HTTP/1.1 201 Created

1
```

```bash
curl -X GET http://localhost:8080/likes/12345
```

Пример ответа:

```bash
HTTP/1.1 200 OK

1
```
