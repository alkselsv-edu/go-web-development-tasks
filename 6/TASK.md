# Хранение данных в памяти Go-приложения

В реальных сайтах часто требуется формировать и делиться ссылками на определенные страницы. Например, реклама на любых внешних площадках в итоге должна вести на сайт или ссылки в промо-электронных письмах. Предположим, что на сайте есть страница: *https://site.com/page/one*. Можно везде использовать напрямую этот URL, однако здесь есть существенный недостаток: если URL страницы поменяется, то необходимо его поменять во всех внешних системах, иначе пользователи, переходя по старым ссылкам, будут видеть сообщение "Страница не найдена". Иногда пользователи добавляют страницы в закладки и такую информацию уже не изменить. Чтобы полностью контролировать процесс перенаправления пользователя на правильную страницу, в проектах реализуют специальные сервисы, которые управляют ссылками. Такие сервисы работают по следующей схеме:

1) в сервисе создаются связки ссылок: внешняя ссылка -> внутренняя ссылка
2) внешние ссылки размещаются в рекламе или на внешних площадках
3) когда пользователь переходит по внешней ссылке, веб-приложение получает от сервиса внутреннюю ссылку и перенаправляет пользователя на нужную страницу
4) если в определенный момент необходимо изменить/удалить внутреннюю ссылку, то в сервисе к существующей внешней ссылке привязывается новый URL

## app/solution.go

Реализуйте веб-приложение, управляющее связками ссылок. Веб-приложение должно уметь обрабатывать следующие HTTP-запросы:

* `POST /links` с телом `{"external": "string", "internal": "string"}`. При таком запросе связка ссылок сохраняется в оперативной памяти. Если в памяти уже существует такая внешняя ссылка (external), то значение внутренней ссылки (internal) перезаписывается. В ответ веб-приложение отправляет статус код *200 OK*.
Если при парсинге тела запроса возникла ошибка, то должен вернуться ответ со статусом `StatusBadRequest` и телом `Invalid JSON`.

* `GET /links/{external}`. Этот запрос по переданной внешней ссылке возвращает ответ: `{"internal": "string"}`. Если запрошенной связки не существует, то должен вернуться HTTP-ответ со статусом `StatusNotFound` и телом ответа `Link not found`.

Так как в HTTP-запросе `GET /links/{external}` внешняя ссылка является частью ссылки нашего веб-приложения, она будет передаваться в URL-кодированном виде. Например, если внешняя ссылка `http://example.com/`, то в запросе она будет выглядеть как `http%3A%2F%2Fexample.com%2F`. Чтобы получить из такой строки исходную ссылку, нужно ее декодировать. В Golang для этого есть готовая функция `url.QueryUnescape()`.

Разберем работу веб-приложения на примере. Допустим, отправляется HTTP-запрос на создание новой связки ссылок:

```bash
curl -X POST http://localhost:8080/links -d {"external": "https://short.com/kwz", "internal": "https://google.com/search?q=hello"}
```

Веб-приложение сохраняет связку в памяти и присылает ответ:

```bash
HTTP/1.1 200 OK
```

После этого, мы можем запросить связку HTTP-запросом:

```bash
curl -X GET http://localhost:8080/links/https%3A%2F%2Fshort.com%2Fkwz
```

В ответ веб-приложение возвращает соответствующую полную ссылку:

```bash
HTTP/1.1 200 OK

{"internal": "https://google.com/search?q=hello"}
```

Если же запросить несуществующую ссылку:

```bash
curl -X GET http://localhost:8080/links/invalid
```

То веб-приложение вернет HTTP-ответ:

```bash
Link Not Found
```
