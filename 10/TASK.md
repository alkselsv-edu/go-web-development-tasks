# JWT-авторизация на сервере

В этой практике вас предстоит реализовать систему аутентификации и авторизации с использованием jwt-токенов. 

Схема работы веб-приложения следующая:

## app/solution.go

1. Пользователь отправляет HTTP-запрос на регистрацию с логином и паролем:

```bash
POST /signup

{"email": "john@doe.com", "password": "qwerty123"}
```

Веб-приложение хранит созданных пользователей в переменной `users map[string]User`, где ключ — это электронная почта пользователя, а значение — структура со всеми данными пользователя. Если пользователь с таким email уже существует, то возвращается HTTP-ответ со статусом *409 Conflict*. В случае успеха веб-приложение сохраняет пользователя в оперативной памяти и возвращает HTTP-ответ со статусом *200 OK*.

2. После успешной регистрации пользователь может пройти аутентификацию. Для этого он отправляет следующий HTTP-запрос с логином и паролем:

```bash
POST /signin

{"email": "john@doe.com", "password": "qwerty123"}
```

Если пользователь отправил некорректные учетные данные, то веб-приложение возвращает HTTP-ответ со статусом *422 Unprocessable Entity*. В случае успеха веб-приложение генерирует JWT-токен для этого пользователя и возвращает HTTP-ответ со статусом *200 OK* и JWT-токеном в теле:

```bash
HTTP/1.1 200 OK

{"jwt_token": "xxxxx.yyyyy.zzzzz"}
```

Для подписи JWT-токена необходимо использовать секретный ключ, который хранится в переменной `secretKey string`.

3. Когда пользователь прошел аутентификацию он может запросить данные своего профиля. Для авторизации пользователь передает JWT-токен в заголовке HTTP-запроса *Authentication*:

```bash
GET /profile
Authorization: Bearer xxxxx.yyyyy.zzzzz
```

Веб-приложение авторизует пользователя по JWT-токену и возвращает данные его профиля. Если не передать JWT-токен или передать некорректный, то веб-приложение возвращает HTTP-ответ со статусом *401 Unauthorized*.
